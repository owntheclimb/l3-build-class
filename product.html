What Ships Today

Not a demo, not a toy: a real feature, in your own repo on the company platform, taken through the exact loop the engineering team uses every day. The feature is deliberately small so the LOOP can be the star.

1 Read the codebase 2 Plan 3 Build 4 Test to the gate 5 Brutal audit 6 Pull request 7 Land + deploy

The feature: a Suggestion Box

Everyone builds the same small feature so the whole room converges: an improvement-ideas box where anyone can see suggestions from the floor and the office.

The data

A suggestions table: title, details, who submitted it, status, timestamps. One migration, one model, one factory, one seeder with five sample rows.

The API

GET /api/suggestions returns every suggestion as JSON, newest first. A real endpoint another app could call tomorrow.

The page

/suggestions lists them in a clean table, styled the way THIS codebase styles pages, not the way a template generator would.

The tests

Feature tests for endpoint and page, plus their evil twins: the empty table, the boundary-length title, the wrong method.

The pipeline you will ride

The moment your pull request opens, the platform starts judging your work. This is the part most classes never show you, and it is the part that makes it real:

GATE 1

The test run. The pipeline executes the repo's test suite against your branch. Red suite, no ship.

GATE 2

The coverage check. This platform requires strong test coverage on both backend and frontend. Untested code is politely refused, no matter how good it looks.

GATE 3

The robot reviewer. An AI code reviewer reads your diff and leaves a review, finding by finding. We will read its verdict together, out loud, and answer it like professionals.

LANDING

The merge and the deploy. On the trainer's go, the branch merges into qa and the platform deploys it to the QA environment automatically. You watch your feature go live on company infrastructure.

If a gate rejects us live in class, nothing went wrong. That is the system doing its job, and handling a rejection calmly is a skill this class deliberately practices.

Why this feature, and not something flashier

Your first sessions were about the ground: the environment, the files, the setup that fought back. Today the ground pays for itself. A deliberately small feature keeps every minute on the thing this level exists to teach: the loop that turns AI output into software a company can actually accept. Reading before writing, planning before building, testing because the gate demands it, auditing your own work brutally, and shipping through review.

The feature changes next time. The loop never does. Learn the loop once, and every future idea is just a different Prompt 2. The homework prompt hands you the flash: make it beautiful, then ship that beauty through the same loop, on your own.
